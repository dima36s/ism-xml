# ИСМ XML

Веб-приложение для машиночитаемых регламентов интегрированной системы менеджмента (ИСМ). Сейчас в нём опубликована методика **C2.4.1.MTH.01 «Методика по разработке функциональных моделей информационных систем»**, версия 1.0, статус «проект».

**Открыть приложение:** https://dima36s.github.io/ism-xml/

Источник истины — XML-файл по схеме `urn:protech:ism:regulation:1.0`. Приложение читает его прямо в браузере и строит из него все представления. Чтобы изменить содержимое, правьте XML, а не страницы.

## Что умеет приложение

| Вкладка | Что там |
|---|---|
| Документ | Полный текст регламента с исходной нумерацией и карточкой документа в виде штампа. Под каждым пунктом раскрываются его атомарные требования |
| Требования | 48 атомарных требований с фильтрами по модальности, критичности, владельцу, разделу, роли и объекту; выгрузка выборки в Excel |
| Реестр | Карточки в формате корпоративного мастер-реестра требований: ID карточки, владелец, критичность C1–C4, критерий приёмки, статус, комплектность |
| Роли | Кто что делает с ФМ (матрица «роль × действие») и реестр ролей |
| Объекты | Документы, разделы ФМ, диаграммы и элементы нотации BPMN, к которым относятся требования |
| Связи | Семантические связи документа с пунктом-основанием |
| Проверка ФМ | Автоматическая проверка BPMN-схемы по п. 4.2.2 (файл обрабатывается в браузере) и чек-лист экспертизы остальных требований |
| Замечания | 11 замечаний к исходному docx, найденных при переводе в XML |

Меню **«Выгрузить»**: XML документа, XSD-схема, XSLT-представление, реестр требований в Excel, комплект одним архивом. Там же можно открыть другой XML ИСМ со своего компьютера; файл никуда не отправляется.

На любой пункт и любое требование можно дать ссылку: кнопка «Скопировать ссылку» или адрес вида `…/ism-xml/#/req/REQ-C2.4.1-MTH01-3.3-07`.

## Реестр требований

Каждое атомарное требование в XML несёт карточку корпоративного реестра (шаблон пилота V0.1): наименование, владельца, класс критичности C1–C4 с обоснованием, метод верификации и критерий приёмки, уровень L1–L6, статус, версию и рабочий номер `TEMP-…`. Выгрузка «Реестр требований (Excel)» даёт файл со столбцами A–R в том же порядке, что и лист «Реестр» мастер-книги, со списками допустимых значений и формулой комплектности — строки можно вставлять в мастер-реестр как есть.

Владельцы и критичность пока **предварительные** (`status="preliminary"`); правила назначения описаны в замечании EN-12. Подтверждение владельцем — замена `preliminary` на `confirmed` в XML. Постоянные `CR-…` ID присваивает оператор реестра после проверки карточек.

## Структура репозитория

```
index.html, assets/        приложение (HTML, CSS, JS, шрифт Golos Text, JSZip, ExcelJS) — без внешних зависимостей
data/
  C2.4.1.MTH.01.machine-readable.xml   регламент (без ФИО сотрудников)
  ism-regulation-v1.xsd                 схема 1.2: структура, поля реестра, перечисления, контроль ссылок xs:key/xs:keyref
  ism-regulation-view.xsl               XSLT 1.3: HTML-представление без приложения
  build.ps1, build.bat                  сборка HTML из XML в Windows (проверка по XSD, ссылкам и цитатам)
  media/                                рисунки из п. 4.2.2
examples/                  примеры BPMN-схем для вкладки «Проверка ФМ»
tools/validate.py          проверка XML перед публикацией
.github/workflows/         та же проверка автоматически при каждом изменении data/
```

## Как обновить регламент

1. Отредактируйте `data/C2.4.1.MTH.01.machine-readable.xml` (прямо на GitHub или локально).
2. Сохраните изменения в `main`. GitHub Actions запустит проверку: XML должен проходить XSD, цитата каждого требования должна дословно находиться в тексте его пункта, ФИО в публичном файле не допускаются. Проверка также сообщает, сколько карточек реестра комплектны.
3. Через минуту-две изменения появятся по ссылке приложения.

Локально ту же проверку запускает `python tools/validate.py data` (нужен `pip install lxml`).

## Работа без интернета

В меню «Выгрузить» выберите «Комплект одним архивом», распакуйте и запустите `build.bat`. Скрипт проверит XML и соберёт рядом HTML-страницу. Ничего устанавливать не нужно, работает в Windows PowerShell 5.1 и 7.

## Конфиденциальность

Репозиторий публичный. ФИО сотрудников из метаданных документа удалены, должности сохранены. Файлы, которые вы открываете в приложении (свой XML, BPMN-схема), обрабатываются в браузере и на сервер не отправляются. Отметки чек-листа хранятся только в вашем браузере.
