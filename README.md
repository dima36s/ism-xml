# ИСМ XML

Веб-приложение для машиночитаемых регламентов интегрированной системы менеджмента (ИСМ). Загружаете свои документы — Word, PDF, Excel-реестры или XML ИСМ — приложение размечает пункты и атомарные требования, заводит на каждое требование карточку корпоративного реестра, собирает карточки всех документов в общий реестр и подсвечивает пересекающиеся требования. Результат выгружается в XML и Excel.

Для примера в приложении опубликована методика **C2.4.1.MTH.01 «Методика по разработке функциональных моделей информационных систем»**, версия 1.0, статус «проект».

**Открыть приложение:** https://dima36s.github.io/ism-xml/

Всё работает в браузере: загруженные файлы никуда не отправляются, документы и правки хранятся только у пользователя (IndexedDB).

## Как пользоваться

1. **Загрузка.** На главной странице перетащите файлы в рамку или нажмите «Загрузить» в верхней панели. Можно несколько файлов сразу; файлы можно бросить и в любое место страницы. Перед загрузкой выберите уровень требований (L1–L6) и включать ли документ в общий реестр. Один файл сразу открывается на вкладке «Документ».
2. **Документ.** Текст с исходной нумерацией, под каждым пунктом — найденные требования. Кнопка «Разметка: добавить требование» показывает у каждого пункта кнопку для ручного добавления. Переключаться между документами — меню с названием документа в верхней панели или список слева.
3. **Карточка.** Кнопка «Изменить» у требования открывает карточку реестра: формулировка, цитата, владелец, критичность C1–C4 с обоснованием, область применения, метод верификации, критерий приёмки, уровень, статус, версия. Поля, без которых карточка остаётся «Заполнить», отмечены точкой. Там же требование можно удалить.
4. **Общий реестр.** Карточки всех документов, отмеченных «в общем реестре», в одной таблице с фильтрами по документу, владельцу, критичности, комплектности и пересечениям.
5. **Пересечения.** Пары похожих требований из общего реестра: «почти совпадают», «пересекаются», «противоречат по модальности» (одно обязывает, другое запрещает). Общие слова подсвечены, порог сходства настраивается. Ложные пары отмечаются «не дубль».
6. **Обмен с коллегами.** Меню «Выгрузить»: XML документа, реестр документа в Excel, общий реестр в Excel и XML, всё одним архивом. Коллега загружает полученный XML у себя.

## Что умеет разметка

| Источник | Что получается |
|---|---|
| Word .docx | Разделы и пункты по стилям заголовков и нумерации Word, таблицы, термины, сводная информация и история изменений в метаданные |
| PDF | Разделы и пункты по нумерации в тексте; таблицы и рисунки не восстанавливаются |
| Excel-реестр .xlsx | Каждая строка листа с заголовками шаблона V0.1 — карточка со всеми полями A–R |
| XML ИСМ | Открывается как есть, без повторной разметки |

Требование — предложение с модальным словом: «должен», «следует», «необходимо», «обязан», «не допускается», «запрещается», «рекомендуется», «допускается». Перечень после «должен включать:» даёт отдельное требование на каждый пункт перечня. Дословная цитата сохраняется в `<quote>` и проверяется по тексту пункта. Каждой новой карточке присваивается рабочий номер `TEMP-ГГГГММДД-NNN`, статус «Черновик» и версия 0.1; владельца и критичность назначает человек.

Пересечения ищутся по словам формулировок без учёта окончаний (стеммер Snowball для русского языка) с весами TF-IDF: редкие слова значат больше, частые — меньше. Требования одного пункта между собой не сравниваются.

## Вкладки документа

| Вкладка | Что там |
|---|---|
| Документ | Полный текст с исходной нумерацией и карточкой документа в виде штампа. Под каждым пунктом раскрываются его атомарные требования |
| Требования | Атомарные требования с фильтрами по модальности, критичности, владельцу, разделу, роли и объекту; выгрузка выборки в Excel |
| Реестр | Карточки документа в формате корпоративного мастер-реестра: ID карточки, владелец, критичность C1–C4, критерий приёмки, статус, комплектность |
| Роли, Объекты, Связи | Кто что делает, над чем выполняются требования, семантические связи документа |
| Проверка ФМ / Чек-лист | Для опубликованной методики — автоматическая проверка BPMN-схемы по п. 4.2.2; для остальных документов — чек-лист требований |
| Замечания | Замечания к исходному тексту, найденные при переводе в XML |

## Реестр требований

Карточка требования в XML (`<requirement>` с `<registry>`) повторяет шаблон мастер-реестра пилота V0.1. Выгрузка в Excel даёт столбцы A–R в том же порядке, со списками допустимых значений и формулой комплектности — строки можно вставлять в мастер-реестр как есть. Общий реестр в XML — один документ ИСМ: раздел на каждый источник, источник и пункт каждой карточки в `registry/@sourceDocument` и `@sourceClause`, пересечения — замечаниями `duplicate` и `inconsistency`.

У опубликованной методики владельцы и критичность пока **предварительные** (`status="preliminary"`); правила назначения описаны в замечании EN-12. Постоянные `CR-…` ID присваивает оператор реестра после проверки карточек.

## Структура репозитория

```
index.html                 приложение
assets/
  app.js                   рабочее пространство, представления, редактор карточек, выгрузки
  convert.js               разметка Word, PDF, Excel и XML в XML ИСМ
  overlap.js               поиск пересекающихся требований
  store.js                 хранение документов в браузере (IndexedDB)
  app.css, fonts/          оформление, шрифт Golos Text
  vendor/                  JSZip, ExcelJS, pdf.js — лежат в репозитории, внешних запросов нет
data/
  C2.4.1.MTH.01.machine-readable.xml   опубликованный регламент (без ФИО сотрудников)
  ism-regulation-v1.xsd                 схема 1.3: структура, поля реестра, перечисления, контроль ссылок
  ism-regulation-view.xsl               XSLT: HTML-представление без приложения
  build.ps1, build.bat                  сборка HTML из XML в Windows (проверка по XSD, ссылкам и цитатам)
  media/                                рисунки из п. 4.2.2
examples/                  примеры BPMN-схем для вкладки «Проверка ФМ»
tools/validate.py          проверка XML перед публикацией
.github/workflows/         та же проверка автоматически при каждом изменении data/
```

## Как обновить опубликованный регламент

1. Отредактируйте `data/C2.4.1.MTH.01.machine-readable.xml` (прямо на GitHub или локально).
2. Сохраните изменения в `main`. GitHub Actions проверит XML: соответствие XSD, цитата каждого требования дословно в тексте его пункта, ФИО в публичном файле не допускаются. Проверка также сообщает, сколько карточек реестра комплектны.
3. Через минуту-две изменения появятся по ссылке приложения.

Локально ту же проверку запускает `python tools/validate.py data` (нужен `pip install lxml`).

Правки, сделанные в приложении, сохраняются только в браузере того, кто их сделал. Чтобы опубликовать их для всех, выгрузите XML и замените им файл в `data/`.

## Работа без интернета

В меню «Выгрузить» выберите «Комплект документа архивом», распакуйте и запустите `build.bat`. Скрипт проверит XML и соберёт рядом HTML-страницу. Ничего устанавливать не нужно, работает в Windows PowerShell 5.1 и 7.

## Конфиденциальность

Репозиторий публичный. В опубликованном регламенте ФИО сотрудников удалены, должности сохранены. Файлы, которые вы загружаете в приложение, разбираются в вашем браузере и на сервер не отправляются; документы, правки карточек, отметки «не дубль» и чек-листа хранятся только в этом браузере. Очистить их можно кнопкой «Удалить все загруженные документы» на главной или очисткой данных сайта.
